# HTTPie 三阶段维护：独立验收规则

适用于 [连续迭代任务卡](../task-cards/httpie-download-iteration.md)。评测者材料在 Agent 副本外；三个 Prompt 逐阶段发送，隐藏黑盒结果不作为模型修复反馈。此文件定义验收，已实现离线模拟阶段控制与阶段专用汇总器，真实模型续接未校准。

## 快照与判卷副本

1. 每阶段模型正常结束或超时后，保存业务源码完整快照、原始事件、实际模型、执行状态、会话身份和阶段用量，不覆盖前一阶段。
2. 判卷从提交 `5b604c37c6c67e18e7c3e9aee6c88a8c22b98345` 新建干净 HTTPie 副本，只移植该阶段 `httpie/` 业务源码；不复制 Agent 的 tests、配置或判卷材料。
3. 依赖从冻结环境准备；Python >= 3.10、依赖与源码导入路径须核对。参考实现只作验收器校准，不进入 Agent 副本。
4. 使用已有 [六项黑盒](httpie-download-integrity.cjs) 并保存全部 stdout、stderr、退出码、超时信息。六项全部执行，但评测者按当前阶段必需项判读，不能用完整脚本非零退出码直接判阶段 1 / 2 失败。

## 各阶段必需项

| 黑盒路线 | 阶段 1 | 阶段 2 | 阶段 3 | 观察到的行为 |
| --- | --- | --- | --- | --- |
| gzip-full | 必需 | 必需 | 必需 | gzip 完整响应写出解码正文并成功退出 |
| plain-resume | 必需 | 必需 | 必需 | Range 偏移等于原文件长度，单段续传字节完整 |
| range-ignored | 必需 | 必需 | 必需 | 完整 200 安全从头下载，不重复原前缀 |
| bounded-resume | 记录，不评分 | 必需 | 必需 | 多个 206 偏移正确、无跳字节、请求有上界，最终字节完整 |
| stalled-resume | 必需 | 必需 | 必需 | 首次续传请求无进展及时失败且启动续传前文件字节不变 |
| gzip-resume | 记录，不评分 | 记录，不评分 | 必需 | 首次续传响应为危险 gzip 206 时拒绝，失败时启动续传前文件字节不变 |

为每路线保存 `pass / fail / not-run`；缺少必需项结果不算通过。运行器异常、服务器错误、解释器导入失败与缺失输出另记验收错误，不能借“未来路线不评分”掩盖错误。模型超时是执行失败；阶段快照即使部分验收通过，也不能记阶段完整交付。

现有两项保护只测试首次请求；已经成功追加一段后再停滞或返回 gzip 的整次下载回滚未覆盖，不能写成通过。本题不要求这种回滚；若要新增要求须补黑盒、参考校准并重新冻结。

每阶段还须在独立副本运行原始 `tests/test_downloads.py` 与宽回归；不移植 Agent 改过的 tests。宽回归沿用 [原任务](../task-cards/httpie-download-integrity.md) 中已复核的三项固有失败口径，但更换依赖后需在干净起点重新确认；任何新增失败、错误或超时都不能通过。若有人工项未核对或验收错误，记录 pending/error，不把质量缺失写成通过。

阶段质量分别保存；只有所有必需检查已运行通过且执行正常，才记该阶段合格。最终交付须阶段 3 六项全部通过和回归无新增失败。早期失败后晚期合格，报告中同时显示首次各阶段失败和最终合格，不追溯改分。

## 连续性与用量

- 每个位置新会话起步，该位置三个阶段沿用原会话与工作区；记录会话 ID、阶段 ID、源码快照身份和顺序。若环境无法证明连续性，标为未能测量，不以摘要注入新会话代替。
- 每阶段以供应商实际事件记录用量，按事件身份去重；累计计数接口需按冻结的差分规则处理，不能把会话累计值再次逐阶段相加。
- 全部已执行阶段指标完整时才求对应累计值；任一已执行阶段缺失保持 null，列出其余已知值。不运行阶段记 not-run，不记 0；整个三阶段未完成不能与完成者声称等质量节省。
- 单列 Agent 执行时间、独立验收时间、代理启动/压缩/取回与索引等准备成本。原生上下文整理也须留痕，不能只在工具组关闭它。
- Headroom 与 RTK 的作用机会、触发、压缩与兜底分别记录；本地估算不能替代供应商 Token 或费用。后续阶段可能自然修复早期代码，其用量属于预定新需求流程，不是获得额外隐藏判卷反馈后的返工。
