## 启动门槛

1. 在正式计时前为每次调用备好相同依赖、构建产物、本地服务和隔离缓存；每次从固定提交新建干净副本与新会话。不得复用试跑补丁或把参考实现交给 Agent。验证启动目录、提交、Prompt/验收器指纹、Codex CLI 版本和模型权限。
2. 运行器使用 `npm run real-dev -- plan` 预览 16 个位置、`npm run real-dev -- preflight` 核对固定输入与环境、`npm run real-dev -- prepare` 在独立副本中离线安装依赖。只有这三步通过后，才可用 `npm run real-dev -- start` 发起 **16 次真实模型调用**；中断后用 `npm run real-dev -- resume <campaign-id>` 续跑。命令串行运行、600 秒进程组超时，记录 JSONL、配置、指纹、退出状态并禁止覆盖已有位置。
3. Memos 每次运行均执行相同的外置组件测试、现有前端测试、类型检查、lint、构建及 [浏览器验收清单](../verifiers/memos-bulk-archive-manual.md) 中的关键流程，特别记录标签筛选、部分失败、统计刷新与网络重试。HTTPie 每次均执行六项外置验收、原有下载测试和宽回归；宽回归的两项 Big5 与一项域名错误文案失败在未改起点已复现，逐项保留，若出现新的失败另判回归。只看 Agent 自写测试不算通过。
4. 质量评审在获知工具组别前按同一口径完成。验收器在 Agent 工作区之外；独立副本只移植 Memos 的 `web/src` 或 HTTPie 的 `httpie` 生产源码，不移植 Agent 修改的测试。两份 Memos 试跑都修改过原有 `home-loading-boundary.test.tsx`；已验证两组生产源码放回干净副本后，原测试因新 React Query hook 缺少查询上下文而失败。运行器先保留**原测试原样执行**的结果，再对所有组施加同一份固定且哈希校验的测试夹具适配（只给三处 Home 渲染包上 `QueryClientProvider`），运行完整项目测试。该适配不改变断言或 mock，独立补丁的组件外置验收另行执行；两份结果都要展示。Memos 的浏览器验收在自动化之后仍标为 `pending`，未完成时不能写质量通过。

## 每次记录与停止条件

每次记录请求模型和可观察到的实际模型、工具注入指纹及可观察激活证据、退出码、超时、外置逐项结果、项目测试、人工复核、耗时，以及供应商 JSONL 的 `input_tokens`、`cached_input_tokens`、`output_tokens`。缓存输入已包含在 input 内：`total_tokens = input_tokens + output_tokens`；仅当两个输入字段都有效时才计算 `uncached_input_tokens = input_tokens - cached_input_tokens`。缺失值保持 `null/未知`，不以 0、字符数或工具自报值替代。`actualCostUsd` 在无供应商计费明细时保持 `null`。

- 单次验收失败、工具未观察到激活、超时或模型调用错误：保留该位置及原始错误，不用“成功重跑”替换；可继续其他位置，并在报告中区分失败类型。Ponytail 指令注入只能证明配置生效，不自动证明每条规则被遵循。
- 明确的额度耗尽、速率限制、认证失效、模型回退、CLI/项目/依赖版本漂移、指纹不符、隔离失效或验收器自身不可用：停止派发**后续**调用，保存已完成位置和停止原因。修复环境后仅继续未开始位置；若不可恢复，则发布不完整结果，不重新挑选顺序或排除失败组。
- 不根据中途 token 差异、成功率或“看起来已足够明显”提前停跑。若资源使全部 16 次无法完成，明确报告已完成分母，不推断未完成位置。不得自动购买额度或切换模型。

报告按任务展示每组成功/失败/未验证数和每次 token；有用量的失败样本仍显示用量。仅在一对两次用量都有效时计算该对 token 差额，并同时标注两次质量；另列缺用量配对数。四对只够展示波动和方向，不能宣称统计显著、质量等效或跨项目稳定省钱。视频只能说“在这两个项目、这套环境中观察到……”，并给出适用场景、激活条件与失败例子。

## Cursor 与其他工具的边界

Cursor **编辑器 Agent** 使用用户指定的 Claude 模型，先重新核对模型标签、版本、用量 hook 与后台 Usage 明细能逐代对账，并验证待测工具在编辑器内确实可激活。Cursor 中也只能比较同一编辑器/同一 Claude 模型的 baseline 与工具组；不能把 Codex CLI 的 GPT token 当作 Cursor 结果，或把两边的原始 token 相加。如果激活或计量不可验证，该工具在 Cursor 栏写“未能测量”，不借用 CLI 数据补位。Cursor 的运行顺序、样本数、手工操作规程与指纹需在其正式调用前单独写定。

RTK、Headroom、CodeGraph、Caveman 不自动塞进上面的 Ponytail 配对。先为各工具选有实际作用机会的任务，离线确认接入与激活证据，再预注册各自 baseline 对照；例如 RTK 要有足够长的测试/构建输出。未触发时保留“未触发”，不能算“无效”或“省了 0”。视频最终按**编辑器/CLI × 工具 × 场景**给安装建议；只有被测且质量可接受的格子才能给出肯定建议。
