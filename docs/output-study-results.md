## 解释范围

- 固定 RTK 0.49.0／7efbaef462911f0fcb112c8a01025dc90f280617，Headroom 0.39.1／d13e1966f820220b482a33c30bde1e926743939a；构建 SHA256 见 JSON。
- 四次重复只覆盖一个三阶段维护任务，可用于决定是否在相似工作流试装；不能推断所有仓库、模型或任务。
- 已核对请求及原生会话中的 GPT-5.6 Sol／medium 标签；供应商实际解析的后端模型快照未知。
- 总 tokens 包含缓存输入；未缓存输入另列。供应商费用、历史安装编译时间和真人维护时间未知。
- Codex 订阅额度消耗未单独测量，不能由 Token 差异直接推算。
- Headroom 为记录明确的 native-offline 配置，保留最近回合保护；Kompress 及 fallback、缓存、memory、image 均禁用。本结果不覆盖这些功能。
- Headroom 请求经过代理但未改变输出时记 schema-or-route-only，保留为未压缩样本。工具字符缩减不等同于供应商用量或费用缩减。
- 独立原始测试的三项已知上游失败保留；额外失败、跳过范围和补验见审计记录。
- 2 个反馈回合同时列出了已知上游失败；可能引发额外修复。成本全部保留，反馈范围与远程测试波动使单组差异不能直接归因于压缩。
- 2 个 chunked 上传超时快照各另作一次同条件定点诊断，并与固定原始起点对照；不调用模型、不改原成绩，也不排除返工成本。诊断结果见 JSON，仅用于核对外部波动假设。
- RTK 对固定版本 git diff --no-index 会返回空输出；rtk proxy git diff --no-index 保留原始输出。

- RTK 的 Hook 不改写带 .venv/bin/ 前缀的 pytest/python 命令，裸命令可改写。自动改写次数不等同于成功压缩次数。

## 使用建议

| 工具 | 对本次日常维护工作流的判断 | 适合试用的场景 | 保留或关闭的条件 |
|---|---|---|---|
| RTK | 有条件试装；本轮没有证明总用量稳定下降 | Agent 经常执行 RTK 支持的命令，终端输出较长，并且 Hook 真实触发 | 先核对原始与过滤输出。需要完整 diff 时使用原生命令或 `rtk proxy`；出现空输出、关键错误信息丢失，或实际命令根本未触发时，关闭对应过滤路径 |
| Headroom | 不建议仅为本次工作流省 tokens 而默认安装 | 历史上下文反复携带大量工具输出，可在这类工作流做独立配对试用 | 必须核对原生命名 provider 和实际输出变化；只有独立验收保持、重复试用观察到用量收益时再保留。仅经过代理、质量下降或用量持续增加时关闭 |

RTK 四组总用量变化分别为 **-29.0%、+172.6%、-33.2%、+21.2%**，两组降低、两组增加；未缓存输入有三组降低，中位数 -22.0%。因此可据此选择相似工作流做小范围试装，不能承诺稳定省额度。固定版本的 `git diff --no-index` 空输出问题和 `.venv/bin/` 命令未改写是明确的使用限制；不要为了制造触发而改变实际任务的命令习惯。

Headroom 四组总用量变化分别为 **+102.8%、+28.0%、-48.0%、+1.0%**，一组降低、三组增加，中位数 +14.5%；未缓存输入中位数 +8.0%。四次均观察到输出改变，仍未证明这套配置在本维护任务中节省端到端用量。该判断只覆盖本次固定的 `native-offline` 配置，不能推断其他压缩配置。

两个首次失败回合分别遇到 `test_chunked_form` 和 `test_chunked_json` 的 3 秒远程请求超时。随后对未修改的失败快照及固定原始起点，各做一次相同条件定点测试，四次均通过、源码未改。该结果支持外部请求波动假设，不能证明工具导致或避免超时；原始失败、额外修复及两次反馈的全部用量均计入以上数字，未改分或剔除。

安装编译、真人维护时间、实际费用及订阅额度变化均未知，不能计算投资回报或省钱比例。此前取消近期保护的重复日志探针只证明该探针可以压缩并保留指定错误标记，没有证明本次正常保护配置或长日志工作的端到端收益。
