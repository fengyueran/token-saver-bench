# Memos 批量归档：正式任务候选

状态：**Codex CLI 单次试跑与重点浏览器验收已完成，未进入正式比较**。这是基于真实开源项目设计的新增功能任务，不冒充上游已有 Issue。

## 固定起点

- 仓库：`usememos/memos`，提交 `b1fa9aefcc22fde5774b7f6cf0b3e19fc67acc6e`。
- 任务类型：日常前端功能开发；需要理解现有列表、卡片、归档操作及查询刷新逻辑。
- 每次运行使用该提交的独立副本和新会话。依赖安装、构建预热和验收器准备在计时外完成。
- Codex CLI 与 Cursor 编辑器 Agent 可以执行同一任务，但必须按环境和模型分别报告；原始 token 不跨环境合并。

## 给 Agent 的任务说明

> 在 Memos 的首页增加“批量归档”功能。用户进入选择模式后，可勾选当前已经加载的、自己拥有的普通 Memo，一次归档所选内容。选择模式应能取消；归档前需要确认数量。完成后列表和相关统计应反映实际结果。如果部分 Memo 归档失败，请明确告知成功和失败数量，并让失败项仍可重新操作。不要改变单条 Memo 的现有归档行为，也不要让其他用户的 Memo 或评论进入批量操作。

英语界面进入选择模式的按钮应有可访问名称 `Select memos`；中文界面使用 `批量归档`。其余按钮和每个勾选框也应有说明操作对象的可访问名称。

## 独立验收口径

1. 首页单列和多列布局都能选择至少两个符合条件的 Memo；未加载的 Memo 不会被隐式选中。
2. 其他用户的 Memo、评论、已归档 Memo 不可进入选择集；服务端授权仍由现有 API 保证。
3. 取消选择模式和切换首页筛选或空间后，旧选择不会作用到新列表。
4. 确认前不调用 `updateMemo`；确认后 Agent 为每个被选中的 Memo 至多调用一次 `updateMemo`，更新字段仅为 `state`。现有客户端传输层对失败响应的自动重试单独记录，不算作 Agent 再次调用；重复网络请求数量仍须披露。
5. 全部成功后，所选 Memo 离开普通列表，统计刷新。部分失败时，实际成功/失败数量可见，失败项保留可重试；不能显示“全部成功”。
6. 原有单条归档、搜索和列表分页仍可用。项目现有前端测试、类型检查和生产构建通过。

外置测试和浏览器验收记录见 `verifiers/memos-bulk-archive.test.tsx`、`verifiers/memos-bulk-archive-manual.md`。当前外置测试覆盖入口、单列/多列目标选择、部分失败、首页标签筛选清空选择；未修改起点 5 项均失败（RED），隔离参考实现 5 项均通过（GREEN）。浏览器另已核对两组全成功后的列表与侧栏标签统计刷新、原有单条归档，以及 Ponytail 的真实筛选问题。尚未逐项核对搜索、分页和评论等全部条件，因此 5/5 与 4/5 仍只是外置组件测试结果。

浏览器复核修正了失败定位：真实界面切换空间会重新装载首页，两组均清空选择；Ponytail 在首页点击标签筛选时仍保留旧选择模式和勾选，而 baseline 清空。外置测试已改为模拟标签筛选并对两组、未修改起点、隔离参考实现重新校准，结果仍为上表的 5/5 与 4/5；模型运行未重做。浏览器还发现：人为让一个 `UpdateMemo` 返回 500 时，**两组**都对失败 Memo 发出两次网络请求；界面都正确报告成功 1、失败 1，并保留失败项。为消除原“请求”一词的歧义，验收口径现明确区分 Agent 的 `updateMemo` 调用与传输层重试；这次澄清发生在单次试跑之后，原始 Prompt、记录与组件测试结果不追溯改写，正式批次须使用冻结后的同一口径。详情见人工验收记录。两组都只有一次，执行顺序和服务端缓存可能影响 token，且实际美元费用未知；这些数字不能当作通用节省率或视频排名。

当前外置测试断言每个目标只调用一次 `updateMemo`，真实传输层在 500 后会重试失败请求；这属于两组共同的底层行为，不能隐去，也不能直接算作某一组的独有缺陷。若将来改为要求严格的网络至多一次，需另建任务版本并对所有组重新运行，不能事后调整旧样本的质量分。第二个不同类型任务已选为 [HTTPie 下载完整性](httpie-download-integrity.md)，正式运行顺序见 [协议](../docs/real-development-protocol.md)；本试跑不参与最终排名。

后续独立验收补充发现：只把试跑的 `web/src` 放进固定起点的干净副本，两组的原有首页测试都因缺少 React Query 上下文而有 3 项失败；固定起点原样运行这 3 项通过。baseline 和 Ponytail 试跑都改过这份原有测试，故此前“项目测试通过”指各自工作区内的结果，不能当作未经 Agent 修改的上游测试通过。现已给所有正式组设同一份固定测试夹具适配，只给原测试中的三处 Home 渲染包上 `QueryClientProvider`，不改断言或 mock，并**同时保留适配前失败与适配后完整套件的结果**；在人工浏览器复核前，Memos 质量仍记未完成。
